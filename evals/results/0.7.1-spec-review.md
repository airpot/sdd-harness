## Finding

### F1. P2: Source-root resolution hides a junction before the installer checks it

Locations: `scripts/install.py:55-56` and `scripts/install.py:31-33`.
Contract: `specs/sdd-harness.md:61` (`PACK-2`); `references/install.md:10-11`.

`install()` obtains its source through `Path(__file__).resolve().parents[1]`.
When the distribution root is a Windows junction, this operation replaces the lexical source path with its ordinary destination.
The later `is_link(root)` check in `skill_files()` cannot identify that original source-root junction.
The source-root guard therefore does not reject every source reparse point before traversal, as the accepted correction requires.

An independent bounded Windows reproduction copied the fourteen portable files into a temporary `source` directory, created `source-link` as a real junction to it, and invoked:

```text
python -B <fixture>/source-link/scripts/install.py --into <fixture>/installed
```

The actual junction check returned true for `source-link`.
The installer returned exit code zero and `{"status": "installed", "files": 14}`.
It created the destination skill. The fixture and junction were then removed through the same Python process.
No external content or production directory was used.

Minimum correction: inspect the lexical source root before `resolve()` can hide the link, as the distribution builder already does at `tools/package_skill.py:28-31`.
Add an actual source-root junction regression, including the no-`Path.is_junction` process, that requires rejection before destination creation.
Retain the current checks for nested source entries, target inventories, and final targets.
This finding does not request parent-directory hardening, a new runtime, or stronger concurrency guarantees.
