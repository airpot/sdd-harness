## Restore Environment

Restore obtains a copy of `os.environ` and asks the installed Git for `rev-parse --local-env-vars` before creating output.
If discovery fails, restore raises an error before output creation.
It removes the reported repository-local names from the copy, using case-insensitive name comparison for Windows.
It passes the resulting single dictionary to initialization, target-path checks, fetch, HEAD update, index construction, and final checks.
The helper's default remains unchanged for inspect and snapshot.

This procedure follows Git's [foreign-repository hook guidance](https://git-scm.com/docs/githooks) and [local variable definition](https://git-scm.com/docs/git-rev-parse#Documentation/git-rev-parse.txt---local-env-vars).
It uses Git's current list rather than a hard-coded list of three overrides.
The recorded local list contains fifteen names:

`GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CONFIG`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`, `GIT_OBJECT_DIRECTORY`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_IMPLICIT_WORK_TREE`, `GIT_GRAFT_FILE`, `GIT_INDEX_FILE`, `GIT_NO_REPLACE_OBJECTS`, `GIT_REPLACE_REF_BASE`, `GIT_PREFIX`, `GIT_SHALLOW_FILE`, and `GIT_COMMON_DIR`.

Repository-local configuration overrides are removed because Git includes them in that list.
Configuration key/value slots have no active count after `GIT_CONFIG_COUNT` is removed.
Other settings are retained, including `GIT_TRACE`, `GIT_EDITOR`, and global/system configuration selectors.
The code does not assign to `os.environ` or change host settings.
A real trace-file regression confirms that `GIT_TRACE` remains active, and a direct API regression checks the caller environment before and after restore.

Before fetching, restore checks the actual Git directory, common directory, worktree root, and index path against the new output.
Before success, it repeats those checks, requires the output's own index file, checks HEAD against the archive, and checks the index against HEAD.
For an unborn source, `read-tree --empty` creates the output's own empty index; HEAD remains unborn.
Working-file hashes remain checked independently of the index, so dirty and deleted file recovery retains its existing behavior.
